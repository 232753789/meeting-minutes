# 会议纪要插件需求与设计交接

本文是 `@deepseek-ai/dsh-meeting-minutes` 的中文交接参考，供下一任务智能体在当前工作树上继续开发、验证和提交。插件使用方式以 [`README.zh.md`](../README.zh.md) 为准，设计理由以 [Browser meeting minutes Agent Note](../../../../.agents/notes/implemented/feature/2026-08-19-browser-meeting-minutes.zh.md) 为准；本文集中记录用户需求、当前实现、环境状态和后续工作。

## 一、目标和范围

插件在现有 DeepSeek Harness Web 项目上提供完整的会议纪要流程：浏览器本地录音或上传已有 MP4，Host 保存原始文件并统一生成 MP4/AAC，Qwen3-ASR-1.7B 生成不区分发言人的全量文字，Harness LLM 生成会议主题和会议纪要，页面以历史清单进入单个会议，展示结果并下载 Markdown、转写原文与原始音频。

用户确认的要求如下：

- 功能作为独立包 `packages/meeting/meeting-minutes` 实现，产品代码尽量不修改其他包；确需修改的仓库注册、构建、目录清单、测试支撑和文档必须明确影响。
- Web 浏览器使用 `MediaRecorder` 录音；Host 接收浏览器支持的音频或视频格式，保留原始文件，并统一转为 `audio.mp4`。浏览器不承担转码。
- 会议产物包含原始录音、标准化 MP4、全量转写、模型总结和可下载 Markdown。
- 对话框打开时显示历史录音清单：第一列名称在已生成总结时使用 Markdown 文件名，否则使用上传文件名或已存录音文件名，第二列显示会议目录的创建时间；点击一行进入该会议的下载页。
- 清单页提供上传入口，只接受 mp4 文件；上传的会议开始与结束时间由浏览器读取的媒体时长和文件修改时间推导，读不到时长时两者相同。
- 下载页不再提供“重新录音”。已完成或失败的会议都显示“重新解析”，并可下载转写原文。新录音从清单页开始。
- 清单每行末尾提供删除按钮，删除整个会议目录（含原始录音）；点击后在行内二次确认才真正发送请求。正在处理中的会议不可删除，按钮禁用。
- 清单最多显示 5 行，更多会议在清单内滚动，表头保持可见。
- 插件配置页（设置 → 插件 → 插件配置）出现会议纪要卡片，可修改文件路径与 ASR 相关配置；保存后立即生效，不需要重启。
- 纪要文件名最后一段是录音时长分钟数（如 `_5m`），向上取整且不小于 1，不再是结束时间。
- 转写默认在本地执行，不区分发言人；允许通过配置显式切换本地或远程 ASR，但失败时不得自动改变音频目的地。
- 本地 ASR 使用 Hugging Face `Qwen/Qwen3-ASR-1.7B` 的完整模型目录，通过 `qwen-asr` 直接加载两个 safetensors 分片，不经过 Ollama。只有 `model-00001-of-00002.safetensors` 不能运行。
- 默认存储目录为 `$DSH_HOME/meeting-minutes/<meeting-id>/`，`storageRoot` 可改为其他绝对或可展开路径。
- Markdown 文件名由会议日期、开始时间、模型识别主题和结束时间组成，并可直接下载。
- ASR、音频转换或总结模型失败后，已有 `meetingId` 的失败页显示“重新解析”；重试复用已经保存的原始录音，不要求重新录音。
- 页面提供“下载原始音频”；上传被 Host 接受后，该下载在处理中、失败和完成状态均可用。
- 麦克风授权失败、浏览器不支持录音或上传尚未成功时没有 `meetingId`，页面只允许重新录音，不显示“重新解析”或原始音频下载。
- `$DSH_HOME/settings.yaml` 不是插件组合配置入口；插件配置位于 `$DSH_HOME/profiles/web/cordis.patch.yml`。该 settings 文件是否存在不影响插件加载。

## 二、明确不做的内容

- 不做发言人分离、声纹识别或虚构发言人身份。
- 不做词级或短语级时间对齐；转写时间戳只表示固定 ASR 分片的起点。
- 不修改 `agent-loop`，不把插件自动加入仓库随附的 Web profile。
- 不在本地失败后自动调用远程 ASR，也不在远程失败后自动加载本地模型。
- 不从已完成的 ASR 分片或总结请求中间续跑；“重新解析”从格式转换开始完整重跑。
- 不提供局域网或公网访问。当前 HTTP 路由只有回环 Host 与同源检查，没有用户认证。

## 四、处理流程

0. 对话框打开时 Client 请求 `GET /meetings` 渲染历史清单；`phase === 'idle'` 即清单页，其余阶段属于某一个已打开的会议。
1. Client 依次探测 MP4、WebM、Ogg 的 `MediaRecorder` MIME 支持，申请带回声消除、降噪和自动增益的麦克风流。上传路径改为读取所选文件：`endedAt` 取文件最后修改时间，`startedAt` 取其减去媒体时长，并通过 `x-meeting-source-filename` 传递百分号编码的显示名称。
2. 用户点击“结束并提交”后，Client 将录音 Blob 作为原始请求体提交，并通过 `x-meeting-started-at`、`x-meeting-ended-at` 传递 ISO 时间。
3. Host 在读取请求体前检查回环 Host、`Origin` 和 `Sec-Fetch-Site`，按 `maxUploadBytes` 流式写入仅所有者可访问的原始文件，写入 `metadata.json` 后返回 `202` 与 `meetingId`。
4. 串行运行时把状态更新为 `normalizing`，FFmpeg 先生成 128 kbit/s AAC 的 `audio.mp4`，再生成 16 kHz、单声道、PCM s16le WAV 分片。
5. ASR 按分片顺序执行，每完成一个分片更新 `completedChunks`。本地模式复用一个常驻 Python 进程；远程模式把 WAV 作为 base64 `audio_url` 发送到配置的 chat-completions endpoint。
6. 全部分片完成后，Host 原子写入 `transcript.json` 和 `transcript.txt`，状态进入 `summarizing`。
7. 短转写直接进入最终总结；超过 `summaryMaxInputBytes` 时先分段总结，再逐层缩减。每一轮必须减小总输入，否则失败；总轮数受 `summaryMaxReductionRounds` 限制。
8. 最终模型只返回含 `topic` 和 `summaryMarkdown` 的 JSON。Host 写入 Markdown 后才把状态改为 `complete`。

浏览器本地阶段为 `idle`（清单页）、`requesting → recording → uploading`（新建会议）和 `opening`（从清单打开），随后映射持久阶段 `queued → normalizing → transcribing → summarizing → complete | failed`。执行重新解析时临时进入 Client 状态 `retrying`，服务端接纳后回到 `queued`；“返回列表”回到 `idle` 并重新拉取清单。

## 五、ASR 设计

### 本地模式

`asrMode: local` 在插件加载时校验完整模型目录，缺少任一必需文件都会在注册 HTTP 路由前失败。Python worker 在第一个分片到来时加载模型，后续分片和会议复用该模型；插件释放、请求取消或超时会终止 worker 进程树。

`localDevice: auto` 依次尝试 CUDA、Apple MPS 和 CPU；只有该模式允许从不支持的本机加速设备退到 CPU。显式 `cuda`、`mps` 或 `cpu` 不做设备回退，任何本地错误都不会转向远程 endpoint。

必需模型文件为：

```text
config.json
generation_config.json
chat_template.json
preprocessor_config.json
tokenizer_config.json
vocab.json
merges.txt
model.safetensors.index.json
model-00001-of-00002.safetensors
model-00002-of-00002.safetensors
```

预期下载命令为：

```bash
hf download Qwen/Qwen3-ASR-1.7B \
  --local-dir /Users/andy/Documents/src/models/Qwen3-ASR-1.7B
```

### 远程模式

`asrMode: remote` 使用 OpenAI 兼容 `/v1/chat/completions` 音频内容格式。`remoteEndpoint` 是完整 URL，`remoteModel` 是请求模型 id，`remoteApiKeyEnv` 只保存环境变量名称；环境变量为空时不发送 bearer token。单分片请求受 `asrRequestTimeoutMs` 和 `asrMaxOutputTokens` 限制。

## 六、总结与 Markdown

总结通过 `ctx.llm` 发起独立辅助模型请求。未配置 `summaryProvider` 与 `summaryModel` 时使用当前默认 Agent 模型路由；两者必须同时配置，不能只填写一个。

转写和中间摘要被明确视为不可信数据，模型不得执行其中的指令。最终纪要与会议主要内容使用相同语言，包含会议概览、关键讨论、决策和行动项；缺失信息写“未记录”，不虚构负责人、期限或发言人。每次请求的 provider、model、system、input、token 上限和输出写入 `summary-requests.json`。

Markdown 结构为会议主题、会议 ID、开始和结束时间、原始录音链接、MP4 链接、会议纪要、全量转写。全量转写按 ASR 分片起点显示 `[HH:MM:SS]`。

文件名格式为：

```text
YYYY-MM-DD_HH-mm_<模型主题>_<分钟数>m.md
```

日期和开始时间按 `timeZone` 生成，末段是 `endedAt - startedAt` 向上取整的整分钟数，最小为 1。主题先做 NFKC 归一化，路径和文件系统危险字符替换为 `-`，连续空白和连字符折叠，最多保留 40 个 Unicode 字符；清理后为空时使用 `未命名会议`。同一会议目录中发生重名时，在 `.md` 前追加 meeting id 的最后六位。

## 七、持久文件与权限

每个会议使用一个不可由浏览器直接指定的 Host 生成 id，格式为 `meeting-YYYYMMDDTHHMMSS-<12 位十六进制>`。默认目录如下：

```text
$DSH_HOME/meeting-minutes/<meeting-id>/
├── metadata.json
├── original.<浏览器格式>
├── audio.mp4
├── transcript.json
├── transcript.txt
├── summary-requests.json
└── YYYY-MM-DD_HH-mm_<模型主题>_<分钟数>m.md
```

目录权限为 `0700`，文本与上传文件权限为 `0600`，metadata 和文本产物通过原子写入发布。浏览器提供的 MIME 只映射到 Host 固定文件名，如 `original.mp4`、`original.webm`、`original.ogg`、`original.mp3` 或 `original.wav`，不能选择任意路径。

持久阶段为 `queued`、`normalizing`、`transcribing`、`summarizing`、`complete`、`failed`。Host 重启后首次读取一个非终态且不在当前活动集合中的记录时，将其持久化标记为 `failed`，随后允许用户重试。

## 八、HTTP 接口

路由前缀为 `/meeting-minutes/api`，会议集合前缀为 `/meeting-minutes/api/meetings`。

| 方法与路径 | 成功 | 语义 |
|---|---:|---|
| `GET /meetings` | `200` | 按创建时间倒序返回最多 `listMaxMeetings` 条历史清单；损坏的 metadata 被跳过 |
| `POST /meetings` | `202` | 原始媒体流上传；要求开始/结束时间头和 `audio/*` 或 `video/*` content type，可选 `x-meeting-source-filename` |
| `GET /meetings/<id>` | `200` | 返回阶段、进度、音频可用性、主题、转写、总结、Markdown 文件名或错误 |
| `DELETE /meetings/<id>` | `200` | 永久删除会议目录；处理队列正占用该会议时返回 `409` |
| `POST /meetings/<id>/retry` | `202` | 接纳一个持久 `complete` 或 `failed` 且当前不活动的会议，复用原始录音完整重跑 |
| `GET`／`HEAD /meetings/<id>/original` | `200`／`206` | 以 attachment 下载原始录音，保留原始 MIME 和 Host 固定文件名 |
| `GET`／`HEAD /meetings/<id>/audio` | `200`／`206` | 播放或读取标准化 MP4；尚未生成时返回 `409` |
| `GET`／`HEAD /meetings/<id>/transcript` | `200`／`206` | 以纪要文件名下载 `transcript.txt`；尚未生成时返回 `409` |
| `GET`／`HEAD /meetings/<id>/minutes` | `200`／`206` | 下载最终 Markdown；尚未生成时返回 `409` |

不存在的会议返回 `404`，错误方法返回 `405`，非终态状态或已活动会议的重试返回 `409`，不支持或越界的 Range 返回 `416`。上传还可能返回缺少时间、空请求体或无法解码的 `x-meeting-source-filename` 的 `400`、跨站或非回环请求的 `403`、超限的 `413` 和媒体类型错误的 `415`。

该限制只防止 DNS 重绑定和跨站浏览器访问，不构成身份认证。通过 LAN 主机名或 LAN IP 打开的页面会被拒绝。

## 九、失败与重试

处理队列一次只运行一个会议，以控制 1.7B 模型内存。任意转换、ASR、总结、文件写入或模型输出校验错误都会把 metadata 标为 `failed` 并保存错误文本；已经写入的原始录音、MP4 和转写不会因后续失败被删除。

删除与重试共用同一个同步占用机制：`remove(id)` 在第一次异步读取前占用 id，处理队列正持有该会议时直接返回 conflict，因此不会在 FFmpeg 或 ASR 正在写入时删掉目录。删除成功后整个 `<meeting-id>/` 目录连同原始录音一并消失，不可恢复。

`retry(id)` 在第一次异步读取前同步占用 id，避免两个 HTTP 请求同时通过“读取失败状态再入队”的竞争。只接受持久阶段为 `complete` 或 `failed` 且不在活动集合中的记录；第二个并发调用返回 conflict。

接纳后保留原始录音，清除 metadata 中的分片计数、标准化音频、转写、主题、总结、Markdown 文件名和错误字段，再从 `normalizing` 开始完整执行。固定文件名的 `audio.mp4`、转写和总结审计会覆盖更新；旧的主题 Markdown 可能留在目录中，但 metadata 只指向本次成功产物。

Client 在轮询得到 `meeting.stage` 为 `failed` 或 `complete` 且已有 `meetingId` 时显示“重新解析”，并提供“返回列表”。只有麦克风或浏览器能力失败、尚未产生 `meetingId` 时才显示“重新录音”。重试请求失败时保持失败页并显示“重新解析失败”。

## 十、配置

默认配置来自 [`cordis.patch.yml`](../cordis.patch.yml)，部署覆盖位于 `$DSH_HOME/profiles/web/cordis.patch.yml`。

插件同时注册 `meeting-minutes` 设置命名空间，用户层覆盖组合层。插件配置页的卡片可编辑 `storageRoot`、`asrMode`、`language`、`localModelPath`、`pythonExecutable`、`localDevice`、`remoteEndpoint`、`remoteModel`；字段留空即恢复继承。保存前会用与加载时相同的 `resolveConfig` 校验整段配置，本地模型目录不完整时直接拒绝写入。保存成功后 [`src/lifecycle.ts`](../src/lifecycle.ts) 串行地销毁并重建路由、处理运行时与常驻 ASR 进程：正在处理的会议会被中止并记录为失败，解析结果与当前运行配置相同的保存不触发重建。卡片只在挂载了设置界面且 Host 服务该命名空间时渲染。

| 字段 | 默认值 | 用途 |
|---|---|---|
| `storageRoot` | `$DSH_HOME/meeting-minutes` | 会议目录根路径 |
| `asrMode` | `local` | `local` 或 `remote` |
| `localModelPath` | `$DSH_HOME/models/Qwen3-ASR-1.7B` | 完整本地模型目录 |
| `pythonExecutable` | `python3` | 运行 Python worker 的解释器 |
| `localDevice` | `auto` | `auto`、`cuda`、`mps` 或 `cpu` |
| `language` | `Chinese` | Qwen 语言名称；`auto` 表示自动检测 |
| `asrChunkSeconds` | `300` | WAV 分片秒数 |
| `asrRequestTimeoutMs` | `1800000` | 每个 ASR 分片超时 |
| `asrIdleShutdownMs` | `120000` | 本地 ASR 进程闲置多久后终止 |
| `asrMaxOutputTokens` | `2048` | 每个 ASR 分片输出上限 |
| `remoteEndpoint` | `http://127.0.0.1:8000/v1/chat/completions` | 远程 ASR 完整 URL |
| `remoteModel` | `Qwen/Qwen3-ASR-1.7B` | 远程模型 id |
| `remoteApiKeyEnv` | `QWEN_ASR_API_KEY` | 可选 bearer token 的环境变量名称 |
| `summaryProvider`、`summaryModel` | 当前默认 Agent 路由 | 固定独立总结路由，必须成对配置 |
| `summaryMaxInputBytes` | `65536` | 每次分层总结最大 UTF-8 输入字节 |
| `summaryMaxOutputTokens` | `4096` | 总结输出上限 |
| `summaryMaxReductionRounds` | `8` | 最大归并轮数 |
| `summaryRequestTimeoutMs` | `600000` | 每次总结请求超时 |
| `maxUploadBytes` | `2147483648` | 最大上传字节数 |
| `listMaxMeetings` | `200` | 历史清单返回的最新会议条数 |
| `timeZone` | Host 进程时区 | Markdown 文件名时区 |
