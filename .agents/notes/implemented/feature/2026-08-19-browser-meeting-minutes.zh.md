# Agent Note: 浏览器会议纪要

Status: implemented

[English](2026-08-19-browser-meeting-minutes.md) | 中文

## 问题

Web 应用需要一条可选的本地优先路径，把麦克风录音转为持久会议音频、完整转写、总结纪要和可下载 Markdown 文件，同时不耦合 `agent-loop`，也不改变随附的 Web profile。

## 决策

`@deepseek-ai/dsh-meeting-minutes` 是可安装的 Web profile 组合包，包含 Client 录音器和 Host 处理运行时。安装会添加一条补丁配置，随附的 Web profile 保持不变。插件默认在 `$DSH_HOME/meeting-minutes` 下为每场会议保存一个私有目录，也允许显式配置存储根目录。

录音采集所选麦克风——系统设备、指定设备或不使用麦克风——并可选择把一次浏览器屏幕共享的系统音频混入同一条音轨，使原生会议客户端的声音也被录下；两项选择都持久化在浏览器存储中，不留下任何音源的组合会拒绝录音，共享若不带音轨则直接判定录音失败，而不是悄悄保留一段纯麦克风录音。浏览器录音结束后上传自身支持的格式。Host 保留该原始文件，只有上传不是 MP4 容器时才用包内 FFmpeg 转换为 MP4/AAC，再从该播放文件切分 16 kHz 单声道 WAV，通过不区分发言人的方式顺序转写各分片，再通过 `ctx.llm` 总结全量转写并发布 `date_start_topic_duration.md`，末段是向上取整到整分钟、且不小于 1 的录音时长。Markdown 先链接原始音频，仅在转换产生了单独文件时追加 `audio.mp4` 链接，再包含生成的会议纪要，以及带粗粒度起始时间戳的所有转写分片。

对话框打开时显示已存会议清单，而不是空录音器。清单一行在生成总结后使用最终 Markdown 文件名，否则依次使用上传文件名和已存录音文件名，并显示该会议目录的创建时间；点开一行即进入该会议的阶段、产物与下载。录音器和 MP4 文件选择器是从清单创建会议的两个入口。打开的会议可以下载保留的原始录音、纯文本转写和最终 Markdown，并对自身重新解析；重新录音从清单开始，而不是从已打开的会议开始。每一行还可以删除该会议，删除会移除整个目录（含保留的原始录音），因此该行要求再点一次确认才发送请求。

选中的文件没有录音时间轴，因此由浏览器推导：文件最后修改时间作为会议结束时间，探测到的媒体时长决定开始时间。探测带固定截止时间，否则一个既不报告元数据也不报错的媒体元素会让上传永远停住。所选文件名以百分号编码作为显示用元数据传递，并被压缩为不含路径的标签；磁盘文件仍使用由媒体类型决定的固定名称，因此浏览器提供的名称永远不能选择路径。

## 设置命名空间与安装替换

组合包在自身组合配置之上注册 `meeting-minutes` 设置命名空间，并以该命名空间为 key 在插件配置页贡献自己的卡片。卡片放在本包而不是与三张随附卡片并列：该界面的槽位契约正是按命名空间设计的，就是为了让插件自持卡片；而客户端 bundle 纯净门禁又排除了引入那个包的卡片外壳，因此卡片在设置 scope 之上自绘控件。

保存被接受后替换正在运行的安装，而不是等待重启。解析后的配置被冻结进处理运行时与常驻 ASR 进程，因此替换是路由、运行时与该进程的完整销毁重建；正在处理的会议会被中止并记录为失败，与插件重载的结果一致。替换是串行的，且解析结果与当前运行配置相同的配置不触发任何安装，因此重新读取文档不会打断会议。

写入使用与 Host 加载时相同的解析流程校验，包含完整本地模型检查，因此插件无法运行的配置在写入时就被拒绝，而不是拖到下次启动才失败。

## ASR 路由

本地模式通过一个常驻 `qwen-asr` Python worker，直接加载完整的 Hugging Face `Qwen/Qwen3-ASR-1.7B` 目录。插件注册路由前要求两个 safetensors 分片，以及配套的 tokenizer、processor、generation、template 和索引文件。自动设备选择依次尝试 CUDA、MPS 与 CPU；本地失败绝不会把会议音频发送到远程服务。worker 把整个模型保留在设备内存中，因此在 `asrIdleShutdownMs` 时间内没有分片处理时会被终止，并由下一个分片重新延迟启动：闲置窗口是重新加载开销与占用加速设备内存之间的部署权衡，所以它是一个经过校验的配置字段，而不是常量。

远程模式连接显式配置的 OpenAI 兼容 chat-completions endpoint、模型 id 和可选 bearer token 环境变量。本地与远程 ASR 的切换是配置决策，不是错误回退。

## 总结边界与持久性

每次总结请求都有输入字节、输出 token、超时和归并轮数限制。长转写先按有界分段总结，再分层归并；每轮归并都必须缩小组合输入。最终 Markdown 发布前，插件会把辅助请求与输出原样写入 `summary-requests.json`。

运行时串行处理会议以限制 ASR 模型内存，上传内容直接流式写入仅所有者可访问的文件；后续阶段失败时仍保留原始录音、标准化音频和已经完成的转写。重试接纳会先同步占用 meeting id，再读取记录；持久状态为 `complete` 或 `failed` 且当前不活动的记录都可以接纳，同一时刻只有一个调用方能够入队。删除以同样方式占用 id，并拒绝处理队列正持有的会议，因此不会在 FFmpeg、ASR 或总结正在写入时移除目录。重新解析已完成的会议同样是一次完整重跑：它覆盖固定名称的标准化音频、转写与总结审计，旧主题的 Markdown 仍留在目录中，而 metadata 只指向新产物。接纳后保留原始录音，清除派生元数据，从头重新执行格式转换、ASR 与总结，并且绝不改变配置的 ASR 目的地。插件释放会移除路由、中止请求与模型任务、终止 Python worker，并等待重试接纳和自有任务停止。Host 重启后会把未结束记录标记为失败，不会无限显示为活动状态，随后可以使用同一重试路径。

## HTTP 访问

清单、原始上传、重试与产物路由只接受回环 Host 值和同源浏览器请求。`GET /meetings` 读取全部会议目录，遇到无法解析的记录时跳过该条而不是让整份清单失败，并按创建时间返回最新的 `listMaxMeetings` 条：meeting id 按录音开始时间排序，而上传较早的文件不遵循该顺序。`GET /meetings/<id>/original` 只提供 Host 选定的原始文件名，`GET /meetings/<id>/transcript` 以纪要文件名提供已发布的转写；`POST /meetings/<id>/retry` 在不存在、冲突与已接纳之间返回明确结果，不会产生先读后入队的竞争；`DELETE /meetings/<id>` 在同一占用机制下返回已删除、不存在或冲突。该限制减少 DNS 重绑定与跨站访问，但不构成用户认证；在 Web 应用提供带认证的路由机制之前，局域网访问仍不可用。

## 考虑过的替代方案

**把功能加入随附的 Web 组合包。** 这会让不需要会议处理的用户也承担模型文件、FFmpeg、存储和录音 UI。该功能因此保持为选择性安装的组合包。

**通过 Ollama 运行本地 Qwen3-ASR。** 选定的 Hugging Face 模型面向 `qwen-asr` 运行时分发，需要两个 safetensors 分片与配套文件。直接加载可保留上游推理 API；远程 OpenAI 兼容服务仍是独立模式。

**只接受一个 safetensors 分片。** 单个分片不是完整 checkpoint。加载期校验会拒绝不完整目录并列出所有缺失文件。

**在浏览器内转码。** 浏览器编解码器与长录音内存行为存在差异。Host 统一使用一条 FFmpeg 路径，使保存的 MP4 与 ASR WAV 输入保持一致。

**为系统音频专门做一个 Chrome 扩展。** `chrome.tabCapture` 与 `chrome.desktopCapture` 走的是与 `getDisplayMedia` 相同的采集管线，扩展拿不到网页请求不到的音频，却要额外维护一个分发物、一套安装流程和页面与扩展之间的传输通道。

**不请求权限就列出麦克风名称。** 在麦克风权限被授予一次之前，`enumerateDevices` 返回的 label 为空，无名列表会让首次选择变成猜测。权限在下拉菜单首次打开时请求——正是需要这些名称的时刻，而不是在打开对话框查看历史记录时。

**共享不带音频时退回纯麦克风录音。** 这样丢掉的恰好是会议的远端一半，而且直到纪要出错才会被发现。该录音被直接拒绝，错误信息指明需要打开哪个开关。

**把每个上传都重新编码为固定的 `audio.mp4`。** MP4 上传本身就是播放容器，重新编码要对长音频多跑一遍，还白白损失音质。只有其他容器才会被转换；metadata 记录实际播放的文件，两种情况下 ASR 分片都从该文件切出。

**从本地 ASR 自动回退到远程。** 会议音频可能包含机密信息。本地失败会直接报告，不改变已配置的数据目的地。

**按浏览器给出的文件名保存上传文件。** 浏览器文件名是可被攻击者影响的输入。它只作为显示用元数据保留，磁盘文件仍使用由媒体类型决定的固定名称，这样清单可读，同时不把任何路径选择权交给浏览器。

**在文件名里保留会议结束时间。** 开始时间与结束时间回答了同一个问题两次，而对比两份纪要的人真正想知道的是各自开了多久。末段因此改为整分钟时长；不足一分钟写作 `1m` 而不是看起来像缺陷的 `0m`。

**只删除生成产物，保留原始录音。** 会议目录里最大的文件就是原始上传，保留它等于没有释放用户想回收的磁盘空间。删除因此移除整个目录，误点由确认按钮防护。

**把卡片放到三张第一方插件卡片旁边。** 这样可以直接复用卡片外壳、字段控件和暂存表单模型，不必重写。代价是把一个可选组合包的文案与控件放进每个部署都会加载的包里，并且颠倒了该槽位契约特意支持的所有权方向。这张卡片小到可以自持，而共享机制无论如何都不是插件 bundle 能引用的。

**让保存在下次重启时生效。** 把命名空间标为 `restart` 可以完全不动运行时与 ASR 进程，代价是卡片上的字段在有人重启 Host 之前悄悄不起作用。替换安装让保存名副其实，而卡片在用户提交前就写明了唯一的代价——一场被中断的会议。

**在 Host 端用 FFmpeg 探测上传文件时长。** FFmpeg 可以精确测量，但只能在上传完成之后，这要么推迟 `202` 响应，要么需要在记录发布后回写开始时间。浏览器在发起请求前就持有该文件并能报出同一个时长。

## 验证

包测试覆盖配置、完整模型校验、文件名与 Markdown 渲染、清单排序与跳过不可读记录、显示名压缩、HTTP 信任、上传限制、清单与转写路由、原始音频下载、两个终态的单次重试接纳、删除已存会议及其在排队时被拒绝、文件名时长取整、串行处理、重试释放、上传时长探测及其截止行为、Client 录音与清单交互、设置命名空间对存储根的替换及其对不可运行配置的拒绝、安装替换与释放、设置卡片的暂存保存与清除、总结收敛和真实 Loader 组装。Web 快照套件会挂载构建后的 Client 组合包，并记录完成结果、从失败到重试成功的界面、从清单打开会议及其逐行删除状态，以及时间戳来自探测时长的文件上传。真实本地模型冒烟测试依赖运行环境，因为 Qwen3-ASR 的加速器支持、内存占用和吞吐会随 Host 而变化。

## 后果

该流程隔离在一个可选包内，并复用既有 Web、子进程、默认模型与 LLM 服务。仓库还需要把该包注册进 Host 与 Client 编译聚合、许可经过审查的 FFmpeg 安装脚本，并维护一个 Web 组装快照。存储会议较多时，每次清单请求都会读取全部会议目录，`listMaxMeetings` 只限制响应条数，不限制读取量。本地部署必须提供安装了 `qwen-asr` 的 Python 与完整模型目录，并在处理长会议前验证加速器容量。
