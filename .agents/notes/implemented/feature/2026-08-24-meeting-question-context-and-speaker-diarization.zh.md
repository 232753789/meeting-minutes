# Agent Note: 面试问题连续上下文与可选会议说话人分离

状态：已实现

[English](2026-08-24-meeting-question-context-and-speaker-diarization.md) | 中文

## 问题

仅按静音切分的 VAD 端点可能在连接成分之后截断一个面试问题，导致回答判断模型分别收到残句和完整问题。会议助手可以转写混合的麦克风与电脑音频，但固定时长分片无法说明每段文字由谁说出。

## 决策

面试助手保留 VAD 作为声音端点，并在 ASR 之后加入确定性的 `QuestionAccumulator`。它会合并以配置的连接短语结尾的片段，在问号或句末边界释放文本，并在一个已有片段包含显式多问题标记时拆分问题，然后为每个稳定问题调用现有的一次回答判断请求。累加器不发起第二次模型请求；socket 关闭时的会话销毁会中止模型工作，因此不会在销毁期间刷新待处理文字。

会议助手增加可选的 `speakerMode: pyannote` 路径。常驻 Python worker 加载本地 `pyannote.audio` pipeline，对标准化录音完整做一次说话人分离，并返回 `speaker-1` 等有序区间。FFmpeg 为每个区间切出临时单声道 WAV，现有 Qwen ASR 路径转写这些文件，转写 JSON、纯文本和 Markdown 保留区间时间与说话人标签。默认的 `speakerMode: off` 继续使用固定时长分片，也不要求安装 pyannote。

说话人标签只在当前录音内有效。它们不是姓名、持久声纹身份或跨会议档案。启用分离时，配置会在加载阶段校验本地 pipeline 目录；分离失败会使会议失败，而不是发布没有标签的文字。

## 备选方案

**把每个 VAD 片段直接交给现有回答判断模型。** 不采用，因为模型收到的用户消息已经把残句当作完整输入，无法稳定地恢复问题，而且请求数增加却没有改善端点判断。

**增加一次 LLM 请求判断问题是否完整。** 不采用，因为它增加延迟，也会产生需要记录的新模型可见输入；连接短语和显式边界已经可以解决当前的截断问题，不需要第二次模型调用。

**运行说话人嵌入匹配并建立持久身份数据库。** 不采用，因为会议助手没有经过同意的注册流程或身份来源；录音内的说话人分离已经能区分声音，也不会把录音变成跨会议生物特征档案。

**改用一个多模态或端到端 ASR 模型直接输出说话人标签。** 不采用，因为这会替换现有 Qwen ASR 路径，需要另一套本地服务协议，并使已经配置当前 ASR 技术栈的部署无法复用。

## 验证

面试助手的累加器和会话集成测试覆盖连接成分合并、多问题拆分、完整性提示，以及片段未完成时不触发判断。会议助手测试覆盖说话人区间校验、常驻 worker 复用、按说话人区间切分 FFmpeg、带说话人标签的转写渲染和续跑布局处理。七个文件的会议聚焦测试共 89 个测试通过。

## 后果

- 面试回答会等到累加文本稳定后才开始，因此以连接成分结尾的 VAD 片段不会单独触发回答；不常见的说法仍可能需要下一段才能完成，且判断仍是启发式的。
- 说话人分离增加一个本地 Python 模型、一次完整录音推理、临时区间 WAV 文件和每个检测到的说话区间的一次 ASR 请求。它默认关闭，并通过配置的设备使用 CUDA、MPS 或 CPU。
- 转写段增加可选的 `speaker` 与 `endSeconds` 字段；只有存在说话人标签时，渲染产物才显示 `[说话人 N]`。
- 未设置 `speakerMode` 的现有部署继续使用固定分片，不需要额外安装可选的 `pyannote.audio` 依赖。
